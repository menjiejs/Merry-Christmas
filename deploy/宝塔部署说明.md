# 宝塔部署说明

这是代码与配置准备说明，尚未连接或修改你的服务器。需要 Linux 宝塔、Nginx、Python 3.10+，使用单机本地持久磁盘上的 SQLite。

## 1. 上传与权限

将项目放到 /www/wwwroot/christmas，包含 index.html、app.js、server.py、requirements.txt、deploy 和 assets 目录（含音乐文件与署名）。不要将临时 __pycache__ 或测试备份作为公开静态文件上传。
创建 data 目录，交由运行应用的普通用户读写；不要以 root 用户运行程序。数据库目录不要放在每次更新会清空的发布目录。

## 2. 安装与启动

在项目目录创建虚拟环境并安装依赖：

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/gunicorn -c deploy/gunicorn.conf.py server:application
```

使用宝塔 Supervisor 管理器添加上面的 Gunicorn 命令：工作目录为项目目录，运行用户为有 data 目录读写权限的普通用户；开启开机启动、异常退出自动重启。使用虚拟环境内 gunicorn 的绝对路径。每次更新代码或样式后重启应用进程。

正式部署不运行 python3 server.py；它保留给电脑本地学习与接口测试。

## 3. 域名、SSL 和反向代理

在宝塔添加站点，绑定实际域名并申请 SSL，开启强制 HTTPS。不要开放 8000 端口到公网。

1. 将 nginx-http.conf 内容加入 Nginx 主配置的 http {}，仅加入一次。
2. 将 nginx-site.conf 内容加入该站点 server {}；保留宝塔现有域名、证书及证书校验路径。删除与模板冲突的旧 location / 和重复限速区。
3. 确认所有业务页面与接口都通过代理访问应用，只有精确的音乐文件路径由 Nginx 读取；不允许通过文件路径读取 data、备份或源代码。
4. 在宝塔检查 Nginx 配置有效后再重载。服务器已有多个站点时，只在当前站点启用这些 limit_conn 指令。

创建链接自动为 https://实际域名/tree/随机编号。无须配置通配子域名或为每棵树单独建站。Cookie 依附域名，www 和不带 www 应选择一个主域名并将另一个重定向。

## 4. 当前限制

- Gunicorn：2 个工作进程，每个 4 个线程，控制应用并行处理数量。
- Nginx：单 IP 最多 10 个正在处理的连接，本站最多 60 个（不是 60 位用户）；慢请求读取 10 秒超时。
- 普通 API：每 IP 平均每秒 5 次，突发 15 次；创建树：每 IP 平均每分钟 6 次，突发 3 次。
- 限流返回 429，繁忙返回 503；页面会提示稍后重试并保留当前填写内容。
- 数据：默认 10000 棵树、100000 次赠送记录（含被移除的装饰），每树最多同时显示 38 枚装饰。达到容量只停止新增，不删除旧留言。
- JSON 提交上限 8 KB。单条留言最多 300 UTF-16 单位。
- 这些是保守的起始配置，并非经过目标服务器压测的吞吐承诺。
- 多人在同一 Wi-Fi 会共用公网 IP，创建树限速可能影响聚会时集中操作；可酌情调整创建突发值，保持平均速率。
- 别加多个独立数据库副本或把 SQLite 放网络磁盘；如需要多机器扩展，需迁移数据库。

如需降低存储上限，通过 Supervisor 环境变量 TREE_MAX_TREES、TREE_MAX_ORNAMENTS 调整，重启服务后生效。TREE_DATABASE 可指定绝对数据库路径。不要删除数据库来“扩容”。

## 5. 备份、日志与磁盘

在宝塔计划任务中每天运行（替换成实际路径）：

```sh
/www/wwwroot/christmas/.venv/bin/python /www/wwwroot/christmas/deploy/backup.py --database /www/wwwroot/christmas/data/trees.db --output /www/backup/christmas
```

脚本使用 SQLite 在线备份接口并做完整性校验。备份目录必须在网站目录之外；在宝塔设置备份保留份数（建议 7 份）和日志轮转，不可无限累积。另留一份异机备份。

容量上限限制业务数据条数，不限制宝塔日志及备份体积，也不能保证其他站点不把磁盘写满。设置磁盘使用告警（例如 80%）和 CPU/内存告警。恢复时先停止应用，保留原 data 文件夹，将选定备份恢复为 trees.db，并清理旧连接残留 WAL/SHM 文件后再启动；首次请在独立测试目录演练，避免误覆盖正式留言。

## 6. 上线验收

- 用正式 HTTPS 地址创建树、刷新、复制链接，另一设备可查看及留言。
- 同浏览器重复赠送被拒绝；两位访客同选一个位置只有一位成功。
- 测试 429/503 提示，不在正式数据上反复写入压测。
- 重启 Gunicorn 后留言仍在；GET /healthz 返回 {"ok":true}。
- app.js 可用 ETag 重新验证缓存，API 为 no-store，避免串用访客状态。
- HTTPS 响应的 Cookie 有 Secure、HttpOnly、SameSite=Lax。
- 正式域名的开发者身份需要重新线下绑定，不会自动继承 localhost 身份；不要提供“填名字即可认领开发者”的公开入口。

仍需提供服务器 CPU/内存规格与实际域名，才能确定最终参数。当前没有执行宝塔配置、HTTPS 验证、正式负载测试或公开发布。
